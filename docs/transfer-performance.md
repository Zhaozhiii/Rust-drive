# 上传、下载性能与稳定性优化

2026-10-29 实现并验证，已于当天 **23:56（Asia/Shanghai）** 发布到 [drive.zhiii.top](https://drive.zhiii.top)。发布版本为 `drive-service:02d1f5f4b803`。

## 实现

- 上传将零碎请求数据合并到固定 256 KiB 缓冲，每路仍然流式写盘，不缓存整个 16 MiB 分片或整个文件。
- 实际写盘在阻塞线程执行，不再占用全局逻辑容量锁。磁盘余量检查通过独立的短锁协调，并计入尚未结束的写入预留量；写入失败或结束时释放预留。
- 分片请求独立持有执行任务，断开连接后会先结束正在执行的写入，再释放同片互斥锁。后台写入的磁盘预留也随实际写入结束释放，避免取消与重试发生交叠。
- 数据同步、原子替换前的提交标记、状态文件同步和目录同步仍然保留。确认成功的分片可以在服务重启后继续使用，接口与会话格式保持兼容。
- 下载路径验证不再等待全局目录锁；递归删除和上传提交的目录同步移出异步工作线程，减少对其他请求的影响。
- 生产 Nginx 配置增加有界文件 I/O 线程池，两个线程、最多 256 个排队任务；下载继续使用 `sendfile`，单次发送最多 1 MiB。Nginx 的线程 I/O 可以避免文件读取和发送阻塞工作进程，要求构建包含 `--with-threads`。见 [Nginx 官方 AIO 文档](https://nginx.org/en/docs/http/ngx_http_core_module.html#aio) 与 [sendfile_max_chunk 文档](https://nginx.org/en/docs/http/ngx_http_core_module.html#sendfile_max_chunk)。
- 浏览器上传超时由“五分钟总耗时”改成“五分钟无进展”，慢速但持续传输的连接可以继续工作。408、429、可恢复的 5xx 错误保留重试；400、404、409、413、507 等明确错误直接暂停。暂停、成功和失败都会清理超时计时器。

## 本机前后对照

WSL Ubuntu 24.04、Rust 1.99.1、Linux musl release、Nginx 1.24.0，Linux 临时文件系统，明文 HTTP 回环；48 MiB 文件，三路并发，每个请求数据块 64 KiB，七轮取中位数。基线是上一轮已经增加 256 KiB 缓冲的版本。两个后端使用相同的新版 Nginx 测试配置，以比较本轮后端改动。

| 指标 | 本轮修改前 | 本轮修改后 |
| --- | ---: | ---: |
| 上传吞吐中位数 | 657.2 MiB/s | 710.2 MiB/s |
| 同时下载时的上传吞吐中位数 | 577.2 MiB/s | 628.4 MiB/s |
| 三路下载合计吞吐中位数 | 4066.7 MiB/s | 4233.4 MiB/s |
| 健康检查与列表两个请求合计 P95 | 7.36 ms | 7.22 ms |
| 后端采样峰值 RSS | 4796 KiB | 3992 KiB |

该场景上传吞吐约提高 8%，混合负载上传约提高 9%。下载是回环且受页缓存影响，两个版本也使用相同的 Nginx 配置；这些下载数字不能证明生产下载速度提升。另一个 4 KiB 请求数据块的短测场景中，两版吞吐接近，说明结果取决于客户端、请求分块、存储和调度条件。RSS 以 20 ms 间隔采样，只包含后端，不包含 Nginx、测试客户端或操作系统页缓存，可能漏掉短暂峰值。

上述性能对照没有覆盖公网、HTTPS、长时间持续写盘、冷缓存或真实服务器磁盘负载。服务器出口带宽、用户上行、时延、丢包及磁盘性能仍会决定实际速度和波动。
